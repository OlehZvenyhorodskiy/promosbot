# Belgium Promos Bot — Project Roadmap & Development Plan

Дорожня карта розвитку проєкту, архітектурних оновлень та інтеграції з GitHub.

## 1. Поточний стан проєкту (Baseline)

- **Telegram Bot**: реалізовано на `aiogram 3` (команди `/start`, `/promos`, `/search`, `/stores`, `/categories`, `/favorites`, `/settings`, `/test_promo`, `/help`).
- **Скрапери**:
  - `Aldi`: витягнення з вбудованого Algolia JSON у `__NEXT_DATA__`.
  - `Colruyt`: селектори промо-карток HTML (`.action-card`, `.promo-card`).
  - `Carrefour`: парсинг схем `JSON-LD` (`Product`, `offers`) з HTML-фолбеком.
  - `GenericRetailerScraper`: базовий HTTP/HTML парсер цін та бейджів для інших 7 мереж.
  - `BrowserRetailerScraper`: Playwright Chromium семафорний фолбек для клієнтського рендерингу (CSR).
  - `NewsletterParser`: прийом вхідних вебхуків розсилок (`/api/v1/inbound-newsletter`).
  - `GeminiFolderParser`: прототип розпізнавання сторінок брошур через `gemini-2.5-flash`.
- **База даних**: SQLite (`src/db/repository.py`) з дедуплікацією за `external_id`.
- **Тести**: 10 юніт-тестів на сховище, пошук, i18n, скрапери та веб-сервер.

## 2. Етапи розвитку та заплановані фічі (Milestones)

### Milestone 1: Повноцінний скрапер усіх брошур та буклетів (Folders Engine)
- [ ] **Підключення платформ цифрових каталогів**:
  - Інтеграція з Publitas API (JSON метадані з хотспотами товарів, знижок та посилань для мереж на кшталт Albert Heijn, Aldi, Carrefour).
  - Скрапінг агрегаторів бельгійських каталогів (Tiendeo.be, Promobutler.be, Reclamefolder.be) як універсального джерела для всіх супермаркетів.
- [ ] **Гібридний обробник PDF/зображень**:
  - Векторне витягнення текстового шару через `pdfplumber`/`PyMuPDF` без втрати якості та без витрат API токенів.
  - Фолбек на `Gemini 2.5 Flash Vision` для сканованих графічних буклетів зі стабільним хешуванням `sha256` замість позиційних ID.
- [ ] **Telegram-інтерфейс для буклетів**:
  - Додати окремий режим перегляду активних щотижневих буклетів (`/folders`) з прямою пагінацією та веб-переглядом сторінок.

### Milestone 2: Розширення списку магазинів та джерел акцій
- [ ] **Нові бельгійські мережі**:
  - `Okay` та `Okay Compact` (мережа Colruyt Group).
  - `Bio-Planet` (органічні супермаркети).
  - `Action` (непродовольчі товари, побутова хімія, снеки, масові знижки).
  - `Kruidvat` (побутова хімія, косметика, напої, щотижневі акції 1+1).
  - `Match` / `Smatch` / `Louis Delhaize`.
  - `Hema` (побутові товари, харчові продукти, пекарня).
- [ ] **Реверс-інжиніринг внутрішніх API**:
  - Перехід з крихких HTML-селекторів на прямі внутрішні каталожні JSON API супермаркетів (Delhaize GraphQL/REST, Colruyt Xtra, Lidl Mobile/Web API).
- [ ] **Акції програм лояльності (Loyalty Cards)**:
  - Підтримка акцій за картками: Xtra (Colruyt), Bonus (Carrefour), SuperPlus (Delhaize), Lidl Plus.

### Milestone 3: Покращення логіки бота та сповіщень
- [ ] **Розумне порівняння цін (Price Comparison)**:
  - Порівняння ціни на один і той самий товар у різних мережах (наприклад, пиво, кава, пральний порошок).
- [ ] **Кошик знижок та список покупок**:
  - Збереження обраних акцій у список покупок з підрахунком сумарної економії.
- [ ] **Групування алертів**:
  - Bounded digest (ранковий або вечірній звіт замість частих поодиноких повідомлень).

### Milestone 4: Інфраструктура та надійність
- [ ] **Персистентна база даних**:
  - Перехід з локального SQLite на PostgreSQL (Supabase / Neon / Cloud SQL) для збереження даних у безсерверному Cloud Run.
- [ ] **Оркестрація фонових задач**:
  - Відокремлення важкого скрапінгу (Playwright, PDF/Vision) від легкого Telegram-бота (Cloud Run Jobs або Celery/Redis).
- [ ] **Автоматичний моніторинг**:
  - Сповіщення адміністратора про збій скрапера конкретного магазину при зміні верстки.

## 3. GitHub Workflow

1. **Гілки**:
   - `main`: стабільна робоча версія, що розгортається на сервер.
   - `feature/<назва>`: нова функціональність (наприклад, `feature/publitas-folders-engine`).
   - `fix/<назва>`: виправлення помилок або адаптація до зміни верстки магазину.
2. **Контроль якості**:
   - Автоматичний запуск тестів через GitHub Actions (`.github/workflows/ci.yml`) при кожному push та PR.
   - Обов'язкова локальна перевірка: `.venv\Scripts\python.exe -m pytest -q`.
3. **Безпека секретів**:
   - Жодних секретних ключів, токенів чи локальних БД у репозиторії.
